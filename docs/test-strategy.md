# 测试策略

## 测试分层

| 层级 | 工具 | 重点 |
|---|---|---|
| 单元测试 | Node.js Test Runner | 活动状态、输入校验、密码与令牌 |
| 接口测试 | Node.js Test Runner + Fetch | 鉴权、CRUD、状态流转、权限边界 |
| Web 端到端 | Playwright + Microsoft Edge | 用户报名闭环、管理员赛事与评价管理 |
| 小程序自动化 | 微信开发者工具 Automation | 首页、详情、登录、个人中心、评价和证书冒烟 |
| 性能测试 | k6 或 Autocannon（下一阶段） | 活动查询、报名并发和接口延迟 |
| 安全测试 | OWASP ZAP 与接口用例（下一阶段） | 越权、注入、暴力登录和敏感信息泄露 |

## 核心质量门禁

- 单元与接口测试全部通过。
- 核心业务状态没有非法跳转。
- 普通用户不能调用管理员接口。
- 未审核评价不能公开。
- 未完赛用户不能生成证书。
- 测试数据库可重复创建，不依赖执行顺序。

## 后续 AI 测试

接口规范使用 `docs/openapi.json`。AI 工具链位于 `ai/`，支持 DeepSeek 真实调用和无密钥离线基线。测试生成与故障分诊报告写入 `reports/`，离线基线不得作为真实模型效果。

### 测试用例生成

输入活动验收标准和接口定义，生成正常、边界和异常场景。生成结果进入人工审核，不直接进入回归集。

评估指标：

- JSON 结构合法率。
- 人工采纳率。
- 需求场景覆盖率。
- 重复用例比例。

### CI 故障分诊

输入失败用例名称、断言、接口响应和前后日志，输出故障分类、根因、证据和修复建议。

评估指标：

- JSON 合法率。
- Top-1 根因准确率。
- 修复建议命中率。
- 平均响应时间。
