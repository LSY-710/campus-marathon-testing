# 校园马拉松项目讲解手册

## 30 秒项目介绍

这是一个面向校园马拉松场景的全栈项目，包含原生微信小程序、普通用户 H5、管理员后台和 Node.js API。用户可以浏览赛事、报名缴费、收藏、提交评价并查看完赛证书；管理员可以维护赛事、报名、成绩、证书、学校和评价。项目的重点不是页面数量，而是把完整业务链路变成可执行、可自动验证的质量体系。

## 3 分钟讲解顺序

1. 用户从首页进入赛事详情，登录后创建报名。
2. 收费赛事先进入待缴费状态，支付后变成已报名。
3. 管理员录入成绩后报名变成已完赛。
4. 管理员可以生成并颁发证书，用户只能看到已颁发证书。
5. 用户提交评价后进入待审核状态，管理员通过后才公开。
6. 系统使用角色鉴权，普通用户不能调用管理员接口。
7. 测试覆盖业务状态、权限、接口、网页端到端和微信小程序页面。

## 核心架构

```text
微信小程序 ─┐
用户 H5 ────┼─ Node.js HTTP API ─ SQLite
管理后台 ───┘
                  │
                  ├─ 角色鉴权
                  ├─ 业务状态机
                  ├─ OpenAPI 规范
                  └─ 自动化测试与 AI 测试工具
```

选择 Node.js 原生 HTTP 和 SQLite 是为了降低演示环境依赖，让接口、数据库和测试流程能够快速启动。生产环境可以替换为 PostgreSQL，并保留现有领域规则和接口契约。

## 三个关键状态机

报名：

```text
WAIT_PAYMENT -> REGISTERED -> COMPLETED
WAIT_PAYMENT -> CANCELLED
REGISTERED   -> CANCELLED
```

评价：

```text
PENDING -> APPROVED
PENDING -> REJECTED
```

证书：

```text
UNISSUED -> ISSUED
```

状态机让测试有明确的前置条件、合法动作和非法动作，而不是只做表单增删改查。

## 测试体系

- 静态校验：检查脚本语法、JSON 配置和小程序页面文件完整性。
- 单元测试：活动状态、报名时间窗口、密码哈希和令牌签名。
- 接口测试：登录、权限、报名、缴费、评价审核、成绩和证书约束。
- Playwright：普通用户和管理员的真实浏览器业务链路。
- 微信自动化：首页、列表、详情、登录、个人中心、评价和证书页面。
- AI 测试：测试用例生成、质量校验、故障分诊和指标评估。

## AI 测试应该如何介绍

当前实现包含两种模式：

- 离线基线：在没有 API 密钥时验证用例结构、去重、覆盖率、分诊结果和评分流程。
- DeepSeek 模式：设置 `DEEPSEEK_API_KEY` 后，真实调用模型生成测试设计和故障分诊。

离线测试使用合成故障样本，100% 准确率只说明规则与评估流程正常，不代表真实模型能力。简历和面试中应明确区分“离线基线”和“真实模型评估”。

## 常见面试问题

### 为什么报名要分成待缴费和已报名？

因为用户创建报名记录不等于完成支付。分开状态可以防止未付款记录占用正式报名名额，也能让支付幂等、支付所有权和状态非法跳转更容易测试。

### 为什么评价需要审核状态？

用户提交内容不能直接公开，否则缺少内容治理。待审核评价不出现在公开接口，管理员通过后才改变可见性，这同时涉及业务状态和权限测试。

### 为什么测试不只做 UI 自动化？

UI 测试执行慢且定位器容易变化。当前采用单元、接口和端到端多层测试：业务规则尽量在单元与接口层发现，UI 自动化只覆盖对用户有价值的关键链路。

### 如何避免测试数据互相污染？

单元与接口测试使用独立内存数据库；Playwright 使用单独的测试服务和内存数据库；微信测试使用固定演示账号。测试执行时避免依赖前一条用例留下的偶然状态。

### AI 在测试里具体做了什么？

当前工具链从需求与 OpenAPI 生成结构化测试用例，并读取失败日志生成故障分类、根因、证据、严重级别和修复建议。生成结果需要人工审核，评估使用标准标签计算分类准确率、修复建议命中率和响应时间。

### 下一步如何提升到生产级？

需要配置真实微信 AppID、HTTPS 域名白名单、微信支付、对象存储、PostgreSQL、统一日志和限流；增加真实 CI 故障样本、更多并发测试和人工复核后的模型评估。

## 简历表述边界

可以写：

- 独立实现用户小程序、H5、管理后台和 API。
- 建立覆盖业务状态、权限和角色隔离的自动化测试。

- 构建需求到测试用例、失败日志到分诊结果的两条 AI 测试工具链。

暂不应写：

- 已接入真实微信支付和生产微信登录。
- 已在生产集群运行。
- 真实大模型准确率达到 100%。
- GitHub Actions 已在远程仓库跑绿。
